2. Problem, Intended Users & Project Summary

Problem

University students frequently struggle to find study partners or form study groups for their courses. There is no centralized, easy-to-use platform to connect students who are taking the same classes. Students rely on informal word-of-mouth, scattered social media groups, or chance encounters — making it difficult to find consistent, organized study support.

Intended Users

University and college students who want to:

  • Find existing study groups for their specific courses
  • Create new study groups and invite classmates to join
  • See who is in a group, where and when it meets
  • Manage groups they have created or joined — all in one place

Short Project Summary

StudyGroup is a web application that lets university students sign up, browse study groups by course, join groups with available capacity, and create their own groups with details like location, meeting time, and member limit. Students can view a member list for each group, leave groups they've joined, and edit or delete groups they organize. The app uses Supabase for authentication and data storage with row-level security, ensuring only authenticated students can access and modify data. The essential user journey — sign up, discover a group, join it, and view its members — was tested and verified end-to-end before submission.

3. Main Features

Authentication (Sign Up / Sign In)

Email and password authentication powered by Supabase Auth. Sessions persist across reloads. No email confirmation required — students get instant access. Error handling for duplicate accounts and invalid credentials.

Discover Page (Browse Groups)

Responsive grid of all study groups, sorted newest first. Live search bar filters by course code, course name, title, or description. Each card shows course badge, title, description, location, meeting time, member count vs. capacity, and "Joined" / "You created this group" labels.

Create Group

Modal form with fields for group title, course code, course name, description, location, meeting time, and max members (default 10). On creation, the user is taken directly to the new group's detail page.

Group Detail Page

Full group info with a member list showing each member's email, avatar, join date, and "Organizer" badge. Join and leave buttons. Creators can edit all fields inline or delete the group. "Group full" message when capacity is reached.

My Groups Dashboard

Two sections: "Organizing" (groups the user created) and "Joined" (groups the user joined). Each row shows course avatar, title, course info, member count, location, and meeting time. Leave button on joined groups.

Responsive Design & UX

Blue-to-emerald gradient brand scheme, rounded corners, subtle shadows, hover lift effects, loading spinners, empty states, and smooth transitions. Responsive grid: 1 column on mobile, 2 on tablet, 3 on desktop. Sticky frosted-glass navigation header.

Database Schema (3 Tables)

Table Key Columns Purpose
study_groups id, title, course_code, course_name, description, location, meeting_time, max_members, creator_id Stores all study groups created by students
memberships id, group_id, user_id, joined_at (UNIQUE group_id + user_id) Tracks which students have joined which groups
profiles id, email, created_at Auto-populated on signup via trigger; stores email for member lists

Row Level Security (RLS) Policies

  • study_groups: All authenticated users can SELECT and INSERT; only creators can UPDATE and DELETE their own groups.
  • memberships: All authenticated users can SELECT; users can only INSERT and DELETE their own memberships.
  • profiles: All authenticated users can SELECT; users can only UPDATE their own profile.
